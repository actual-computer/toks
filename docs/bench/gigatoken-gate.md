## Protocol

One thread, the tier toks_load binds, toks (`tools/bench/e2e.c`) against gigatoken (`tools/bench/gigatoken`, its Rust
API, pinned source) on exactly the same chunks, both on one pinned cpu (macOS: unpinned). Per cell, ROUNDS blocks of
A B B A (A = toks, B = gigatoken); ratio = t_gigatoken / t_toks (> 1 = toks faster), paired rep i with rep i within
each run-pair ((A, B) and (B, A) of a block). **Statistic** (decided 2026-10-05):
the median of the pairs and a 95% cluster-bootstrap interval that resamples run-pairs (a run is the independent unit:
its reps move together), 2000 resamples, tokv1.c's seed. **Each cell's own null decides it**: every round of a cell
also runs a null block A N N A (toks against the same toks), whose pairs give the cell's null median and interval
(6 run-pairs today, 30 at release). **WIN** iff the gate's interval lies wholly above the null's interval widened to
at least [0.99, 1.01] (the 1% tolerance: a lucky 6-pair null cannot certify a 0.5% win), **LOSS** iff
wholly below it, else **TIE** (not a win). The matched configs (warm) take the same cell's default-config warm null.
**Certification is per cell**: a cell whose null |median - 1| exceeds 2% is **UNCERTIFIED SHAPE** and prints so, as
does every cell of an unpinned host (macOS cannot pin); a host's widest null is printed as
context, never as a band. Why per cell, the worked example (tr9970x-avx2's before picture, 2026-10-04): 19 of its 352
null rows exceed 2% (cold 11, pass 5, lang-x 3, warm 0; nearly all cjk / ml, the worst minimaxm2 cjk 4096 cold
1.084). The noise is run-level, not clock-level: a whole process's 5 reps come out slow together (one N run's best
cold 20.95 ms against 18.5-19.4 for the other eleven) while cpu 12 held 5.03 GHz (p90 run-to-run 0.53%, correlation
0.21 with the cold difference): page placement, or memory traffic from builds on the other CCDs, which neither the
sibling, L3 nor load rule sees. The first rule's host-wide band (the largest null, rounded up) gave every tr9970x cell
+-8.5%; the per-cell null keeps cjk cold's noise in cjk cold. n = the pairs (30 at ROUNDS 3, REPS 5). **Cold pairs**
(the gate's rule): a chunked cell's gigatoken runs take ONE cold rep each (its cold forks a vocabulary-seeded
state before every call, 5-60 ms), so its cold n is 6 and the row is provisional (n < 30); the 30-pair cold matrix is a
release-time run. **Void rule** per block (one rule for every row, decided 2026-10-05): the
pinned cpu's smt sibling > 5% busy over the block, or ANY other cpu sharing its last-level cache > 50% busy (a build or
test on the same CCD / cluster shares the cache and memory bandwidth the timed run reads: on tr9970x a make test on CCD1's
8-11 never touched cpu 12's sibling; on gb10b a foreign process at 100% on cpu 5 shares cpu 7's L3 with cpus 0-9 and
marks every block there, so gb10b is no gate host), or the 1-minute load up by more than 2 across it: the block runs
again, and a second such block is VOID (its pairs dropped; the row's n says so). BLOCK lines carry the times and every
L3 cpu's busy share. macOS hosts cannot pin and expose no cache topology: their rows run unpinned, load rule only. A
re-run of a cell replaces it, once, its result taken as it comes: a contended cell, one measured before a rule
existed, one that lost two of its three null blocks to the void rule, or one whose null passed 2% on a state under
100 us while the logs printed microseconds (e2e.c prints nanoseconds from 0980920 on: 1 us was 1.3-2.5% of a warm
pass over the code corpus). States: **cold** (a fresh scratch / fork before every call),
**coldo** (each cold rep after an untimed pass over the OTHER text: a new request after others),
**pass** (after an untimed pass over OTHER text, scratch / state re-initialized), **lang-x** (the timed pass on the
scratch / state the OTHER text left; OTHER = every bench corpus file outside the measured corpus, cut at 4096 bytes:
cross-language, not a same-language warm state), **warm** (the replay right after the pass), **warmo** (init,
a pass over the text, one over the OTHER text, the timed pass over the text, no init between: the serving replay, a
system prompt seen again after other requests) in the declared
cache configs. Exactness per cell, before its blocks: toks' ids == hf's (else VOID); gigatoken's == hf's without the
post-processor (else n/a).

Cold reps are cpu-cache-hot (back to back on one text); coldo's each follow an untimed pass over the OTHER text,
the state a new request meets after others: **coldo is the headline, cold is published beside it**
(decided 2026-10-05). Both tools are measured as their apis are called, which makes their cold differ: gigatoken's cold forks
a vocabulary-seeded state, untimed, right before every timed call, and that fork writes its state into the cpu
caches, so its coldo barely moves; toks' per-call init touches the scratch header only, so toks' coldo carries the
real misses. Per host, coldo against cold (the median and range over its cells of coldo MB/s / cold MB/s - 1):
gb10a-neon toks -1.7% [-42.1%, +9.5%], gigatoken -0.7% [-58.1%, +24.4%] (84 cells);
tr9970x-avx2 toks +2.3% [-5.3%, +28.5%], gigatoken -0.5% [-45.8%, +5.0%] (84 cells);
m2ultra1-neon toks -0.7% [-12.7%, +0.8%], gigatoken -0.3% [-7.5%, +3.5%] (84 cells);
The T8 en bar (encode en-prose >= 600 MB/s per core, set on gb10) reads the **pass** state, cold beside it
(decided 2026-10-05): the Tally's T8 line per host, byte-level bpe tokenizers only (gemma4 is sentencepiece bpe).
